# 在对话里连接和操作应用

日期：2026-10-05 · 代码 v0.12 · schema v11 · agent-v7 / plan-v2。

用户交代目标，妮米选择工具、补齐必要信息、准备操作，在原对话展示成果和真实回执。应用目录提供能力说明与自然语言入口，不再要求用户在目录单独编辑消息、选择事项或跳到地图完成工作。

## 用户流程

1. 直接说“帮我连接企业微信”“整理这份飞书文档，把工作安排发到群里”。也可从应用目录点击“交给妮米”，回到当前对话后修改并发送。
2. 妮米先查询真实能力与连接状态。首次需要配置时，在当前对话展示专用字段。密钥和机器人地址加密保存，不进入模型上下文。
3. 缺少日期、目标或文档链接时，妮米在对话中询问。复杂任务使用计划与 await_actions 保留下一步；用户允许原模型继续后，连接确认会唤醒后续任务。
4. 发送或停用连接先展示目标和具体内容。用户核对后点击确认，真实结果保存在同一段对话中。
5. 已有事项可以在详情点击“让妮米生成日历文件”，回到当前对话，调用模型后交付可预览、下载的真实 .ics 文件。

目录切换不卸载对话，保留当前历史、选择的模型、附件和未发送内容。目录入口追加到已有草稿，不覆盖用户正在写的目标，也不会自动产生模型费用。用户发送后才调用所选真实模型。

## 共享能力合同

Go connectors.Catalog 定义十五项应用的名称、范围、能力与示例；API 的 GET /applications 和 Agent 的 list_applications 使用同一个清单，并结合本空间的连接状态、版本和实际验证记录。没有保存凭据的字段。保存配置和平台成功回执使用不同状态，不能混淆。

| 当前能力 | 实际范围 |
| --- | --- |
| 飞书文档 | 通过官方 SDK 读取用户明确提供且已授权的 docx 正文，不编辑原文档 |
| 飞书、企业微信、钉钉群 | 模型准备文字提案，固定接收群和连接版本；确认后才发送 |
| 系统日历 | 导出真实事项的下一次提醒或截止时间，一个十五分钟事件；用户导入后使用 |
| 联网搜索、高德、邮箱 | 对话配置真实服务凭据后调用搜索、地点/路线、只读收件箱工具 |
| 网页浏览器 | 服务端独立匿名浏览器渲染公开页面；需运行环境启用 |
| 微信、腾讯文档、WPS、12306、美团、购物平台 | 在线账号或交易接口仍未接入，可处理提供的资料 |

不再把高德网址跳转包装成 Agent 地图能力。尚未接入的平台不提供虚假连接按钮或伪造回执。日历文件不代表已写入飞书、系统日历或云日历账号，也不自动同步后续更改。

## 修改和停用连接

request_connection 的 replace=true 在服务端记录当前连接版本，打开内部编辑字段。保存新配置并增加版本后才能确认完成；旧的已启用配置不能完成修改任务。取消连接引导只结束该提案，不撤销已经保存的配置。

propose_disconnect 在服务端读取实际应用 ID、名称和版本，生成待确认提案；模型不能指定版本、替换目标或自行确认。确认接口依次锁定操作、运行、续办和连接，核对最新版本，然后在同一事务清除妮米保存的凭据、停用连接、增加版本并记录审批及续办信号。重复或并发确认只修改一次。连接被修改后，旧停用或群发送提案不能执行。

停用不删除平台账号、群机器人或已经发送的消息，也不撤销已经提交的平台请求。再次使用需重新配置。已成功发送的旧回执仍可以查看，不会因为停用触发重发。

## 日历成果

export_matter_calendar 只读取本空间正在跟进的真实事项。优先使用有效提醒的下一次时间，否则使用截止时间；无时间时返回明确信息，由模型询问并准备修改提案。没有跨空间参数。

复用 golang-ical 编码时间、文本和折行，以 RFC 行结束符输出。文件保留固定事项 UID，正文预览用北京时间。实际标题和导出时间固定在成果幂等标识中，生成后的文件不会因原事项修改而变化。文件及预览通过现有加密本地 / S3 对象层保存，绑定当前对话，可刷新恢复；文件不是未经验证的模型生成 ICS 文本。

## 授权与验收边界

内部工作流不能代替平台首次授权。当前飞书文档需要管理员提供自建应用信息并授权资源，群机器人需要管理员提供连接信息；大众用户的一键 OAuth、飞书日历账号操作、通用邮件 OAuth 和云盘授权仍需实现；QQ/163 等邮箱已有专用授权码只读连接。官方登录或验证码必须由用户本人完成；不能承诺所有第三方登录页都可以放进 Nemi 的 iframe。

v0.11 的专用数据库验证涵盖目录不泄漏凭据、不将未验证配置标为成功、修改必须增加版本、停用前不改凭据、旧版本冲突、十二个并发确认仅停用一次、旧消息被阻止和跨空间隔离。该版23项隔离浏览器验收全部通过，使用真实 API、PostgreSQL 与 Temporal，模型协议替身只编译进测试程序。发布后追加一次只读问询，真实个人模型经过两次请求成功使用 list_applications 并给出答复；没有平台写操作。v0.12 最新验证见[实施记录](./IMPLEMENTATION.md)，完整产品缺口见 [目标跟踪](./GOAL_AUDIT.md)。


v0.12 新增连接沿用同一修改/停用及审批续办合同，具体权限与网络限制见[联网工具](./ONLINE_TOOLS.md)。
