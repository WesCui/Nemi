# Nemi v0.6 实施状态

日期：2026-10-05。[v0.4 验收存档](./archive/v0.4/IMPLEMENTATION.md)保留前版模型与应用配置的范围。

## 本轮交付

- 删除产品的确定性演示生成器及相关入口。所有模型任务需要用户配置的真实 Key 与型号，或运维配置的真实服务端模型。无模型返回 HTTP 412，不创建运行或替代答案。
- 首页是个人 Agent 对话入口，支持多轮上下文、新对话、历史切换、刷新恢复、模型选择、Enter 发送与输入法保护。普通对话不自动创建事项；生活、工作、学习、研究都可从同一入口开始。
- 直接复用 CloudWeGo Eino v0.9.21 ReAct 编排，模型选择工具，执行结果回传给模型继续处理。每轮最多 6 次模型请求、12 次工具调用、10 分钟执行时间；工具顺序执行，单次返回受大小限制。
- 七项工具：北京时间、事项列表、指定事项资料、已保存偏好、应用连接状态、用户明确提供的飞书 docx 文档读取、事项 / 站内提醒提案。工作空间来自认证任务，模型不能选择其他用户、访问凭据或自行确认操作。
- 对话展示执行过程与完整提案卡片。事项 / 提醒待用户点击确认后才写入实际数据；确认与 Outbox 同事务提交，重复确认不重复创建，取消提案和已过期日期不会执行。下一轮注入提案实时状态，区分 pending / approved / declined。
- 每次模型请求先提交唯一步骤 claim、预留费用、检查模型撤销，再调用固定供应商接口；结算每步用量，未知结果保留预算，不自动重发。数据库结算失败和 Worker 中断不擦除已知费用。

原有五个国内模型服务商、AES-256-GCM 凭据存储、飞书文档导入、三个群机器人、事项版本、已确认偏好、站内周期提醒继续保留。飞书使用官方 Go SDK 与已配置且授权的自建应用；目前只有 docx 正文，未接入 OAuth、wiki、附件或写回。群机器人发送仍在应用界面逐次确认，尚未作为 Agent 工具开放。

## 执行与数据合同

conversations / chat_turns 独立保存对话，runs 复用 Outbox / Temporal；schema v7 增加 agent_steps 与 agent_actions。最近最多 10 个成功整轮进入下一次模型上下文，JSON 上限 12000 字节，从最早整轮裁剪；本轮含工具定义与结果的请求 JSON 上限 48000 字节。每空间 100 段对话、每段 200 轮、最多 10 个等待处理的对话，每段至多一个活跃轮次。

个人配置不可变，型号、费用单价、提示合同 agent-v1 / plan-v2 与配置 ID 固定到运行。默认切换不改变已入队任务；撤销阻止后续步骤，在途调用可能完成。API / Worker 共享加密主密钥，凭据不回显、不进 Temporal 参数、业务事件或 Git。模型收到本段历史及本次工具读取的资料，界面明确说明这点。

单轮预算 1 元、每空间每日 3 元（按获准执行的北京日归属）、全局 5 个 / 每空间 2 个活跃运行。多步调用按剩余预留 + 已结算费用占用预算；追加预留使用 admission 同一数据库锁。服务商账单为实际费用依据，配置单价用于本地预算。

隔离浏览器 runner 编译当前版本的测试 API / Worker / Relay，使用独立目录、nemi_test 数据库、随机空间与 Temporal 队列。供应商协议替身只编译进 Go 测试程序，产品没有协议替身或生成回退。

协议测试通过不等于实际模型 / 飞书 / 实群账号已验收。本机目前没有可用于真实外部账号验收的凭据；用户须在模型 / 应用界面填写有效配置、型号及资源授权后调用正式接口。
