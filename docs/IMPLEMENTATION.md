## 运行与恢复约束

当前电脑 3000 端口属于 Windows TCP 保留范围，因此本地预览使用 **http://localhost:3100**，`.env` 的 `APP_ORIGIN` 已对应调整。默认仓库示例仍为 3000；其他电脑可按自身环境选择端口。

本机通过 Git Bash、原生 PostgreSQL 与官方 Temporal CLI 验证，数据保留在被 Git 忽略的 `data`；密钥、口令与缓存不提交。运行步骤见 [开发指南](./DEVELOPMENT.md)。`AGENTS.md` 已约定后续构建、测试与 Git 操作使用 Bash，`scripts/env.sh` 按字面值加载配置，不执行环境文件中的文本。

网页关闭不停止已保存任务。提醒到期不调用模型，Worker 缺席后由 Temporal 保留待执行工作；提醒实际记录前检查最新 enabled / revision。记录出现不等于用户已阅读。

## v0.2 实现合同

日历重复规则复用 `rrule-go v1.8.2`，仅开放 daily / weekdays / weekly；需要明确的首次时间、时区和结束日期，最大两年。结束日期按计划时间判断；22:00 后的免打扰提醒可能记入次日 08:00，界面明确预览。周一至周五不等于中国法定工作日。

周期执行沿用原 Reminder Workflow，不改变已有可重放逻辑。每次交付在同一个 PG 事务中插入通知、递增提醒版本、计算下一次并写 Outbox。新的版本生成独立的 Temporal timer；旧版本重试不会重复交付或推进。当前没有启用目标架构中预留的 Temporal Schedule。停用只停止未来提醒，不中断正在进行的清单生成。

长时间离线恢复时，旧 occurrence 最多留一条 OVERDUE 记录，跳过其余已经错过的时间，再安排下一次未来提醒；不会逐次补发积压通知。提醒已过结束期则停止。交付采用事项 → 提醒的统一锁顺序，避免与用户完成事项产生反向行锁。

每个空间最多 50 条明确确认的偏好；一次生成只选通用或当前场景的最近偏好，最多 8 条、序列化内容不超过 2400 字节。Run 只持久保存偏好 ID / revision，不复制偏好正文。模型提交前按空间与相同 revision 重新读取，已删除或已修改的旧引用会被跳过；新增的偏好不会偷偷加入已排队的 Run。上下文在准入时计入费用预留，提交时只能缩小。

偏好移除会删除当前偏好正文，并影响后续请求，不撤回已经提交给供应商的内容或历史生成结果。命令幂等响应、事件和 Temporal payload 不包含偏好正文；数据库备份、原始资料和已有生成结果的完整删除仍待专门的数据生命周期功能。

本版模型 Profile 更新为 `plan-v2`。更新本地服务时同步替换 API 与全部 Worker；旧 Profile 的排队模型 Run 会以配置已变更终止，不自动产生新费用。旧的长期提醒继续兼容。开源来源和新增依赖许可证见 [开源复用说明](./OPEN_SOURCE.md)。

真实模型调用中断与确定性提醒恢复是不同合同：无可靠下游请求幂等 / 回执时，付费模型请求的结果可能未知。本版不会自动重发该请求，Run 终止并保留未知费用；重试由用户创建新 Run，仍受每日总预算约束。
