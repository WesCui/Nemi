# 国内个人 Agent 产品需求文档

版本：v0.11 · 日期：2026-10-05 · 状态：目标设计；具体完成范围与验证见 [实施状态](./IMPLEMENTATION.md)，完整目标缺口见 [目标跟踪](./GOAL_AUDIT.md)

项目名称 **Nemi / 妮米**；Agent OS / Cloud Runtime 是工程底座名称，不作为面向大众用户的主标题。配套见 [技术架构](./ARCHITECTURE.md)、[dots 功能对标调研](./DOTS_BENCHMARK.md) 和 [使用场景与办公接入调研](./SCENARIO_RESEARCH.md)。原开发者平台方案存于 [v0.1 存档](./archive/v0.1/PRD.md)。

## 1. 产品方向

用户已明确：**专注国内市场，首批用户为大众个人用户，生活助理优先。**

产品提供一个长期协作的通用个人助理，生活、工作、学习和研究共用自然语言入口。用户交代目标，妮米读取获准资料、准备操作、等待必要确认并交付结果；事项和提醒是助理可调用的能力。首次平台权限仍需用户或管理员授权。

当前已交付内部连接卡片、事项/提醒/偏好管理、资料分析与成果，以及有界的确认后后台续办。全平台 OAuth、云端电脑、主动长期研究等仍是目标能力，不能将本版描述为全部实现。用户不必选择工具；下一步计划来自真实模型，等待期间不调用模型。详见 [确认后继续](./CONTINUATION.md)。

用户的主要操作是“说清楚想办的事 → 确认重要信息 → 查看结果或处理决定”。首页提供个人模型配置入口；工具、Workflow 和 Workspace 的实现细节放在工程界面。

**产品承诺：把一件生活事务持续推进到可查看的结果；需要授权、登录或判断时，明确交给用户。**

公开 dots 功能和内部实现的证据边界见对标调研。Go、Temporal、PostgreSQL 等属于本项目的独立选择，不是已证实的 dots 内部技术栈。

### 1.1 当前方案的变化

| 维度 | 当前设计 |
| --- | --- |
| 目标用户 | 国内成年个人用户，先从有多项待办和外出准备需求的人群验证 |
| 默认助理 | 每人一个默认助理，可取名；不要求创建多个 Agent |
| 默认模型 | 平台模型与个人 BYOK；首页配置、默认选择与逐任务选择 |
| 客户端 | 移动 H5 + 微信小程序；Web 承担复杂资料与后续浏览器接管 |
| 核心场景 | 持续生活事务、周末 / 外出准备，资料整理作为共同能力 |
| 办公接入 | 可选企微 / 飞书入口；按授权逐项增加文档、日历、表格，工作资料和个人资料分域 |
| 后端推荐 | Go Control API + Go Durable Runtime + Temporal |
| Python 用途 | P1 的隔离计算与数据处理工具，不承担第二套主任务状态机 |
| 费用体验 | 用户看任务额度和剩余权益；运营后台保存 CNY 成本账本 |
| 部署 | 中国大陆区域的服务与存储，核验各供应商实际数据处理范围 |
| 上线范围 | P0 受控验证；P1 消费级对标内测；公开商业化另有上线条件 |

### 1.2 版本含义

文档版本 v0.5 不等于已完成软件版本。

- **P0 / 生活助理验证版**：验证持续事项、提醒、资料和交付，暂不声称 dots 全功能等价。
- **P1 / 消费级对标内测版**：增加隔离云端工作区、浏览器接管、有界委派、只读主动研究和实时语音。
- **P2 / 扩展版**：本地设备、更多官方应用、家庭协作和规模化商业能力。

P0 约 20–50 名受邀用户，每个个人空间一个 Owner；成年人优先。受邀测试不自动免除适用的上线与数据责任。容量、留存、性能和时间均为待验证目标。

办公接入另用 **C0（消息入口）/ C1（选定内容读取）/ C2（受控写回）** 表示试点能力，独立于 P0 / P1。生活版用户无需组织账户、管理员权限或办公应用配置；办公试点只在获准组织和用户中开放。各阶段工期与平台接入条件单独评估。

## 2. 用户问题与成功标准

### 2.1 重点问题

1. 聊天中形成的计划没有变成能持续跟进的事项。
2. 待办、截图、文件与偏好分散，用户反复解释上下文。
3. 助手做完一轮回答后不再跟进，下一步依赖用户重新推动。
4. 自动化过程不可见，用户不知道是否真的完成、是否需要自己处理。
5. 提醒在渠道失效时静默丢失，或过度主动打扰用户。
6. 用户不愿为了一个生活助手学习模型、API Key 和复杂配置。

### 2.2 首批细分用户假设

| 用户 | 高频事务 | 验证价值 |
| --- | --- | --- |
| 生活待办较多的上班族 | 截止日期、缴费事项、证件材料、个人安排 | 从一句话形成可执行事项，减少忘记和反复查找 |
| 经常安排周末或短途活动的人 | 时间、预算、同行偏好、地点资料、准备清单 | 持续收集与调整，形成能使用的安排 |
| 经常收集截图和文件的人 | 活动规则、报名信息、资料摘要 | 提取关键信息并关联当前事项 |

以上是用户研究假设，不能当成已经证实的市场需求。先验证主场景，暂不全面覆盖购物、金融、医疗、儿童服务或所有本地生活平台。

### 2.3 指标

| 指标 | 定义 | 验证目标 |
| --- | --- | --- |
| 首次价值 | 完成登录后，保存一个正确事项或获得有效清单 | 中位数 ≤ 3 分钟 |
| 激活 | 首周有一个持续事项及两次后续查看 / 修改 / 完成 | ≥ 50% 受邀有效用户 |
| D7 留存 | 激活用户第 7 天附近再次处理实际事项 | ≥ 30%，样本量单列 |
| 事务成功率 | 有明确完成条件的场景由用户或验收确认 | 固定评测集 ≥ 90% |
| 时间理解 | 相对日期、时区、修改与取消不产生静默错误 | 约定测试集全部通过 |
| 提醒可靠性 | 确认渠道可用的应提醒事件具有明确发送状态 | 全部可核对；真实送达率另测 |
| 权限 | 精确审批、撤销、取消按合同生效 | 验收集无越权动作 |
| 成本 | 每次有效事务的模型、语音、计算和通知成本 | 全部记录，不预设无证据低价 |

通知接口接收成功、终端送达、用户打开和事项完成是四种不同事实。仅 Run 结束或通知 API 成功不能证明用户看到了提醒。

## 3. 对标范围与分期

| 能力 | P0：验证版 | P1：对标内测版 | P2 |
| --- | --- | --- | --- |
| 个人助理 | 名称、基础头像、统一身份 | 互动个性化与语音连续体验 | 丰富外观与多个专业助理 |
| 交互 | 中文文字、按住说话转文字、图片 / 文件 | 实时语音、更多输入形式 | 原生 App / 可选桌面入口 |
| 持续事项 | 保存目标、状态、下一步、修改、取消 | 受授权的自主后续检查 | 跨事项依赖 |
| 提醒 | 一次性、周期、时区、静默时段、通知状态 | 更多获准通知渠道与事件来源 | 更广的应用生态 |
| 模型 | 两个经过评测的国内供应商连接，平台代管 | 按任务阶段路由，多模态和高级 BYOK | 私有模型 / 用户自选更多连接 |
| 记忆 | 用户确认的偏好、已办事项、来源记录 | 相关检索、候选记忆和纠正追溯 | 家庭成员分别授权的共享 |
| 资料 | 用户上传和指定公开来源，清单、摘要、文件 | 隔离计算、表格与复杂文档处理 | 更多文件格式 |
| 云端电脑 | 仅受控文件与内置工具，不宣传完整电脑 | 隔离工作区、浏览器会话、用户接管 | 长期环境与本地设备 |
| 委派 | 有限单 Agent 执行 | 最多两个 Child Run、权限与父预算继承 | 更复杂协作 |
| 主动研究 | 仅用户明确保存的职责与检查计划 | 单独授权的只读变化检查 | 更丰富条件判断 |
| 外部行动 | 通知自己和授权范围内的内部事项更新 | 受支持服务的可审批动作与登录接管 | 合作接口的更多业务动作 |
| 可见性 | “在办 / 需要决定 / 已办好”与文件 | 浏览器操作记录、委派结果 | 更丰富回放 |
| 数据控制 | 查看、纠正、删除、导出、授权管理 | 更细的来源和数据类型授权 | 家庭 / 多设备管理 |

P0 不承诺读取全部个人微信、代操作任意 App、监控全部订单、自动抢票、自动付款或绕过验证码。没有 verified connector 的服务仅可整理用户提供资料或跳转到原服务。

## 4. 核心场景

### 4.1 持续生活事务

用户输入：“周五前把报名材料准备好，提前一天提醒我。要求在这张截图里。”

流程：

1. 用户上传截图，助理提取事项、材料、日期和来源；不确定的时间或字段提出简短确认。
2. 展示事项卡：目标、具体截止时间、准备清单、提醒时间、通知渠道状态。
3. 用户确认后保存职责、待办与提醒；申请渠道通知授权时说明它的作用。
4. 助理整理已有资料，缺少的信息以待补充项呈现，可在后台继续工作。
5. 用户后来改为“截止改成周四”，展示将修改的日期与受影响提醒，确认后取消旧版本。
6. 提醒到期走确定性计时与通知，无需再花一次模型调用。
7. 用户查看结果、标记完成，或继续补充资料。原始资料和生成结果分别保存。

验收：确认后的时间准确、重启后提醒仍在、修改后未提交的旧提醒不再发送；已经进入提交点的发送保留在途状态与核对。渠道不可用准确标记，资料缺失不声称已备齐。

### 4.2 外出准备助理

用户描述某次周末外出的日期、出发地、同行人数与预算，以及已有链接或截图。助理准备计划和资料，不在 P0 自动预订。

流程：

1. 确认出行边界、用户偏好与资料可使用范围。
2. 读取允许的公开来源或用户材料，整理候选、交通要点、开放时间及准备清单。
3. 动态信息带来源和核验时间；缺少价格、预约或开放情况时标注需要核实。
4. 用户修改偏好后调整相关部分，保留已确认决定。
5. 保存结果卡与可下载文件；用户可选择授权一次或周期性检查，发现相关变化才提醒。
6. P1 允许在支持的网站打开隔离浏览器，由用户接管登录或最终确认；未完成预订不显示已订好。

验收：结果有来源、修改可追溯、不虚构预订或付款成功、用户离开页面后台资料整理继续、动态信息失效不会伪装为已确认。

两个场景共同验证：长期事项、用户修改、资料输入、后台执行、提醒触达和交付核验。浏览器与自主检查只在 P1 验收通过后开放。

### 4.3 新增场景验证池

本轮调研了十四个候选场景，完整输入、持续行为、权限和指标见 [场景调研](./SCENARIO_RESEARCH.md)。核心仍为个人生活事项；优先用现有能力验证个人承诺收件箱、今日行动清单、差旅 / 报销材料和家居到期。会前准备、会后个人跟进、周报、成人学习与求职可做后续实验。

办公软件先接收用户发给机器人的具体事项，再按许可接入选定日历、文档和结构化表。能与机器人对话不代表能读取所有聊天；有文档链接不代表有读取权。完整公司知识库、会话全量存档与企业管理功能另行定义，场景池不自动全部进入 P0。

## 5. 产品对象与状态

用户看到“助理 / 事项 / 进度 / 需要你决定 / 文件 / 提醒”；工程层继续使用以下模型：

| 对象 | 作用 |
| --- | --- |
| Personal Space / Workspace | 用户数据与授权隔离，P0 不展示复杂空间管理 |
| Agent Definition / Instance | 可版本化行为与该用户的默认助理 |
| Matter / Task | 一次目标或持续事项，可独立修改与停止 |
| Run / Step / Attempt | 一次后台执行、逻辑步骤和实际调用 |
| Reminder / Trigger | 日历语义、计划版本和触发规则 |
| Approval / Operation Intent | 对确定动作的授权与结果账本 |
| Conversation / Message | 多端交流；渠道各自可见范围明确 |
| Memory / Artifact | 偏好与结果，保留来源和删除控制 |
| Notification / Delivery | 通知意图与渠道发送 / 可观测回执 |

Run 状态为 QUEUED、RUNNING、WAITING、PAUSED、CANCELLING、SUCCEEDED、FAILED、CANCELLED。WAITING 原因包括 APPROVAL、USER_INPUT、TIMER、EVENT、CREDENTIAL、BUDGET、RECONCILIATION。

**长期待办和未来提醒可持续数月，Run 的墙钟生命周期默认只有 7 天。** 未来提醒由独立 Trigger 持久保存，在到期时创建短执行；不让一个 Run 或进程等待数月。

事项已完成、提醒已保存、提醒已发送、用户已查看分别显示。停止当前执行、停止持续事项、停用助理也分别处理。

## 6. 功能需求

### FR-01：账户与个人助理（P0）

支持微信小程序登录和合法部署的 H5 登录，默认生成个人空间和一个助理。绑定不同入口要证明同一用户身份，不按昵称、手机号文本或来访 openid 任意合并。登录不等于授予通讯录、聊天、文件或其他服务权限。

首次交互可跳过不必要资料，先完成一件事。名称和基础头像可修改；模型与工具默认由平台配置。

验收：无需用户填写 API Key 即可完成首个事务；账户 A 不能通过 ID、文件、事件流或异步任务获取 B 数据。

### FR-02：生活事项与中文时间（P0）

从对话、语音转写、图片和文本生成可审阅事项卡，明确目标、日期、来源、准备项、提醒和完成条件。“明早”“下周一”基于消息接收时间与用户时区解析；模糊时间、冲突、农历和复杂节假日语义不默默猜测。

默认 Asia/Shanghai，保存原文、解析依据、具体时间和 revision。P0 复杂农历 / 节假日规则要求用户改成明确日期；P1 再实现经过验证的历法和节假日规则。

修改只影响明确事项。批量删除、改日期或新增外部动作须展示影响；保存后的同范围自我提醒不需要逐次审批。

验收：固定日期理解测试全部通过；改期、取消和重复请求不产生额外旧提醒。已进入提交点的旧发送不能承诺撤回，须明确呈现其在途或未知结果。

### FR-03：持续职责与执行（P0）

保存一次目标或持续职责，包含允许的来源、自动范围、完成条件和通知偏好。用户可在原对话继续补充信息，当前执行以版本化命令接收变更，不从头丢失已完成工作。

关闭 H5、小程序进入后台或网络断开均不取消已接收任务。Worker 故障恢复从已提交步骤继续；确认完成的本地步骤不重做。

验收：重启和补充输入期间目标、结果与账本一致；无法核对的外部副作用等待处理，不自动重发。

### FR-04：通知与提醒（P0）

提醒保存与渠道授权是独立状态。小程序订阅消息须按实际账号、模板与用户授权能力发送；一次授权不解释为不限次数推送。腾讯官方文档说明用户触发授权及一次授权对应一条通知。[腾讯官方说明](https://cloud.tencent.com/document/product/1301/103770)

显示站内、订阅消息和可选日历导出等渠道状态。P0 日历为 .ics 下载，由用户导入，不声称自动写入系统日历。没有可用离线渠道时，保存前清楚展示“目前只能在应用内查看”。

计划展示接下来三次时间、静默时段、失效处理和修改规则。一般生活提醒默认不在 22:00–08:00 主动发出；用户设定明确时间与覆盖静默的例外时展示并保存授权。敏感事项的通知预览默认仅提示“有一项待办”，正文进入鉴权页面查看。

验收：无权限、额度耗尽、接口失败或结果不明均准确呈现；过期提醒不在次日盲目补发；接口接受不等同用户已阅读。

### FR-05：生活资料与文件（P0）

支持用户主动上传截图、图片、PDF 和文本；图片 OCR / 识别及 PDF 提取在受控工具中执行。上传和外发模型前展示数据用途，用户可只用于当前事项而不加入长期记忆。

生成事项清单、摘要与安排，可预览和下载。动态信息记录来源与核验时间；未读来源、缺失附件、识别不确定字段单独标记。下载文件与 AI 生成标识按适用规则实现。

验收：来源真实、引用可回查、文件不跨用户、模型虚构的附件或操作不被标成已完成。

### FR-06：平台模型与效果（P0）

平台管理国内供应商账户及配额，优先评测千问和 DeepSeek 的具体型号。用户默认只看适用的速度 / 深入处理档位与额度提示，名称不作为无证据的质量保证。高级设置提供透明的供应商和数据说明。

用能力合同检查工具、图像、结构化输出、上下文和续接字段。只有通过合同与生活场景测试的模型才可执行对应能力。供应商兼容接口与工具调用说明只是适配依据。[千问接口](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)、[DeepSeek 工具调用](https://api-docs.deepseek.com/guides/tool_calls/)

默认回退只在已批准国内处理范围内进行；海外连接和 BYOK 留给后续明确授权的高级路径。运营预算耗尽不能悄悄切到另一个数据边界。

验收：两个供应商完成同一生活工具场景，回退受能力、额度与数据边界限制。

### FR-07：记忆与个性化（P0）

记住用户确认的偏好、选择与进行中事项；用户可查看来源、纠正、删除和关闭。用户说“这次不用记住”只用于当前上下文。

外部截图中的指令、网页描述或工具结果不能提升为用户偏好。P0 默认不长期保存身份证、银行信息、验证码、医疗细节或儿童资料；确需特殊数据时另行确定处理规则，而不是默认采集。

验收：改过的偏好后续生效、撤回记忆不再加载、空间隔离；记忆关闭不删除维持提醒所必需的用户明确保存事项。

### FR-08：动作权限与决定（P0）

用户保存确定提醒或同范围事项授权后，平台可按计划通知该用户；给他人发送、外部发布、账户修改、预订与付款不能从“帮我准备”推断获得授权。

审批绑定目标、参数、身份、内容 hash、期限与当前权限，展示会发生什么。正文变化、目标变化、授权撤销要重新判断。P0 对尚未接入的外部动作提供草稿或跳转，不能展示虚假的批准后执行按钮。

验收：重复批准、迟到批准、参数篡改、撤销与取消竞争窗口全部有正确账本；外部结果未知不会重复提交。

### FR-09：用户控制与可见性（P0）

主页呈现今天需要注意、正在办、需要决定、已完成。用户可暂停当前执行、取消当前执行、停止未来跟进、关闭提醒，界面解释各自影响。

已有副作用、未知交付和在途费用保留；不能以取消状态隐去它们。步骤显示用户可理解的摘要、来源、文件和处理入口，技术堆栈放在诊断视图。

验收：用户能判断是否需介入、是否真正交付，取消生效后不启动新业务动作；已在途动作继续记录核对结果。

### FR-10：语音与跨端（P0 / P1）

P0 按住说话获取音频，完成中文 ASR 后可编辑文本；日期、人名、地址等重要字段显示确认。音频默认完成处理后 24 小时内删除，不进入长期记忆。

P1 实时语音支持打断、文字同步和事项决定。结束通话只结束声音会话，持续事项不自动取消；停止工作需要明确操作。语音识别失败不能创建错误提醒。

小程序与 H5 共享同一助理和事项；不同渠道的消息展示分别管理，不把私人资料无授权发给其他受众。

### FR-11：预算、权益与成本（P0）

内部用 CNY 记录模型、ASR、OCR、搜索、对象存储、计算和通知的估算 / 实际账目；供应商单价与地域固定并版本化。未知费用不是零。

P0 初始运营护栏：每个模型参与的 Run 30 Step、60 个实际模型 / 工具 Attempt、15 分钟活跃执行、7 天生命周期；每个用户同时最多 2 个活跃 Run、全局初始 5 个。确定性提醒使用独立通知执行池和配额，避免长任务占满时错过到期时间。

模型 Run 成本上限暂定 1 CNY、每用户每日后台 AI 成本上限暂定 3 CNY，均为待测的内部护栏，不能作为销售价格或权益承诺；P1 浏览器任务另算并显式告知。

用户看到本次工作需要的权益、剩余额度和降级入口。额度不足时已有提醒仍按已保存交付约定执行；新增高成本任务可等待补充额度。模型、通知和付费渠道分别预留配额；不能用“会员无限次”覆盖不受控的计算成本。

验收：并发不超卖预算、重试不漏账、已承诺提醒不依赖临时模型额度；取消仍可能有在途费用。

### FR-12：云端电脑、委派与主动研究（P1）

这是对标内测版的主要差距项，需单独验收后发布。

云端工作区提供获准文件、隔离代码与浏览器；默认按需创建，保存文件和加密会话，空闲释放资源，不承诺 VM 内存状态永久不丢。用户可在 Web 中接管，Agent 与用户不能同时操作。

最多两个 Child Run，独立上下文、父授权交集和共享成本上限；不允许子任务自扩大权限。

主动研究只读取用户批准的来源和指定事项，设置频率、成本、通知条件与退出入口。自动建议下一次检查仍受范围和频率上限约束，不在 P0 默认持续扫描用户全部信息。

验收：接管时 Agent 停止输入；重新授权才继续；登录秘密不进入聊天；父任务停止传播至子任务；无变化不打扰。

### FR-13：隐私、内容与上线控制（P0 起）

用户可导出、删除事项、偏好、文件与账户。默认保留：工作内容 30 天、产物 90 天；活跃事项和必要提醒字段按持续服务保留至完成 / 删除，个人已确认长期偏好可持续保留至删除并提供过期提醒。原聊天和附件不因此全量无限保留。审计最小化，费用记录按必要性与适用要求单独说明；备份最长 30 天淘汰。在线删除立即撤销读取，目标 24 小时内完成内容清理。

面向境内公众的服务按实际服务形态落实适用要求；调用模型不能代替应用方评估。[生成式人工智能服务管理暂行办法](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)

生成内容标识覆盖适用界面和导出形式，并与来源、结果 ID 一起管理。[人工智能生成合成内容标识办法](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)

公开发布前确认平台类目 / 模板、备案或登记 / 评估适用性、隐私告知与同意、投诉及内容安全流程。具体适用由资质、功能和主管要求确认；本文不是已完成合规的证明。P0 优先成年用户，不推出面向未成年人的专用产品。

### FR-14：办公入口与获准内容（C0–C2 可选试点）

C0 支持通过经安装 / 获准的企微智能机器人或飞书应用机器人提交具体事项，首个原型验证文本单聊与群内明确 @。收到信息后保留来源，确认时间与本人责任，再关联同一助理的事项。群内请求默认只使用群内获准内容，个人私密结果走已验证的私密入口。

C1 逐项验证选定飞书文档、日历 / 忙闲、任务 / 多维表格；企微资源仅按实际接口范围接入。应用身份、用户 OAuth、API 权限、资源 ACL 和组织处理许可分开验证。飞书存在用户身份消息读取权限，但默认不请求全量聊天；企微普通通知 Webhook 不作为群内容读取权限。[飞书官方权限治理](https://www.feishu.cn/content/article/7615520954977881029)、[腾讯官方机器人接入](https://cloud.tencent.com/document/product/1831/137051)

C2 在合同与审批通过后启用特定外部写回，固定目标、日期、正文、参与人和变更影响；未经授权不替用户向同事催办，不把草稿或计划当作完成。平台的交互回复窗口与长期提醒分别配置，不能依赖过期会话继续主动推送。

工作资料、派生摘要、个人记忆和结果受众保留安全域；跨域只在组织和用户授权允许时进行，最低必要忙闲也要检查处理范围。一个组织的机器人可服务多人，但每人 Context / Memory 隔离，群结果不带入私人生活资料。来源权限缩小、用户离职或连接撤销后，停止后续读取、通知与写回，清除相应缓存 / 摘要 / 索引。

验收：C0–C2 各通过其专属 AC-17–20 后开放；未知能力明确显示不可用，用户仍可用 H5 / 小程序完成同一事项。不能把创建 / 安装成功当作所有能力已授权。

## v0.5 个人配置与平台接入实现合同

首页模型设置、逐任务选择与账户凭据以空间为范围，配置不进入 Temporal 历史。personal_models 保存不可变模型、价格和密文；workspace_model_settings 保存默认 ID；runs.model_config_id 固定任务账户。app_connections 保存应用密文、revision 和最近验证时间。撤销在 CALLING 提交前校验，已发起请求不作可撤回承诺。

真实应用合同为：三家群机器人逐次确认发送；飞书自建应用显式认证、指定 docx 只读导入，并保存来源链接。它们不表示已经有用户 OAuth、聊天、日历、个人订单或自动工具循环。[实际验收](./IMPLEMENTATION.md)与[对标范围](./PARITY.md)单独记录。

## v0.5 首页直接对话（已交付）

首页输入框发送给用户选定的真实 LLM，不弹出事项确认表单。用户自行填写 Key 与型号，首模型自动设为默认；缺少可用配置时引导设置并禁止生成。普通回复和多轮历史独立持久保存，支持新对话、切换记录与刷新恢复。真实操作仍在对应事项 / 应用功能中确认；文本回复不作为实际设置提醒或发送消息的证据。

## v0.6 通用个人 Agent（已交付范围）

首页输入框用于向妮米提问、写作、整理资料或提出目标，不默认创建事项。用户自行配置国内服务商 Key 与支持工具调用的型号，所选历史和工具读取的资料会发送给对应模型。无配置不生成替代内容。

模型可按任务选择七项工具：查询事项、读取指定资料、已确认偏好、当前北京时间、应用连接状态、指定且授权的飞书 docx 文档、创建事项 / 站内提醒提案。创建操作在对话中以具体卡片确认，确认后才执行。用户可取消、查看步骤状态、刷新恢复、切换历史与继续任务；超过预算 / 步数 / 时间或供应商失败时显示真实错误。

验收新增：AC-A1 工具返回真实结果且继续交给模型；AC-A2 提案不会提前写入、确认只创建一次、取消 / 过期 / 跨空间操作不执行；AC-A3 每次付费请求有预留和 claim，中断保留已知费用及未知预留、不重复付费提交；AC-A4 无 Key 无网络调用与无替代生成；AC-A5 移动端执行历史和确认卡片可用。

后续能力方向是文件与分析产物、联网检索、隔离云端浏览器与用户接管、长期目标拆分、主动研究、语义记忆和跨渠道入口。以上尚未交付，不能描述为完整 Muse / dots 对齐。



## v0.7 对话驱动的应用工作流（已交付范围）

默认假设用户不熟悉电脑操作。用户只需表达目标，Agent 负责计划、选择工具、读取已授权资料和准备操作；应用连接、补充信息及敏感动作确认在妮米内部的对话卡片中完成。技术配置不进入普通消息；凭据通过专用字段加密保存。

现有范围包括长对话摘要、任务计划与进度、重复调用保护、停止当前执行、连接飞书文档与飞书 / 企业微信 / 钉钉群、继续原任务、读取授权文档和确认发送群消息。配置保存不代表已取得文档权限或消息送达，需显示实际读取结果和投递回执。

首次平台开通仍需用户或管理员授权。微信、邮箱、购物等待接入平台，及浏览器、搜索、文件处理仍待实现；不能将自然语言界面描述为全平台能力已经完成。详见 [harness](./HARNESS.md)。

## v0.11 对话应用工作流

用户通过自然语言完成工作，应用目录只展示真实范围并将目标带回当前对话。Go能力清单同时提供给前端和Agent；连接修改记录原配置版本，停用确认同事务清除凭据并唤醒续办。已有事项可在对话导出真实日历成果。当前工具24项、agent-v6 / plan-v2，schema保持v11；应用OAuth、日历账号读写和云端电脑仍待交付。详见[对话应用操作](./CONVERSATIONAL_APPS.md)。
