# 对话内管理事项、提醒与偏好

日期：2026-10-05 · v0.9。用户描述目标，真实配置的模型选取工具；系统读取本人记录、准备修改卡片，用户在原对话确认后保存。产品没有关键词命中后的固定生成或自动审批。

例如：「把旅行准备第二项标记完成」「在准备清单里加上雨伞」「把截止时间改到下周五」「这件事已经完成」「归档旧的旅行准备」「停掉这个提醒」「改成每天早上九点，到月底结束」「记住我早餐不吃辣」「移除这条偏好」。相对日期先核对北京时间；同名记录、指代或日期不明确时模型应询问用户，不猜测。

## 工具与确认

| 工具 | 合同 |
| --- | --- |
| list_matters / get_matter | 标题搜索、状态筛选、20条分页；读取真实 ID 和事项版本，清单每页10项且带原始索引 |
| get_reminder | 当前提醒、提醒版本、事项版本、状态和截止时间；不存在的提醒为 null，版本为0 |
| propose_matter_update | 标题、完整资料替换、截止修改/移除、状态、清单指定条目修改/移除或追加；一次最多8处清单修改和8条追加，保留其他项 |
| propose_reminder_update | 调整时间、频率、免打扰或结束日期，或仅停用；停用保留原日期与周期设置 |
| list_memories / propose_memory | 当前偏好内容搜索及8条分页；显式请求后的保存、修改或移除提案，不自动保存偏好 |

提案使用已认证的运行空间，模型不能指定其他用户、读取凭据或签发确认。PENDING 只写入 agent_actions，不修改事项、提醒或偏好。完整前后快照用于对话卡片，模型工具结果仅返回 ID、标题与待确认状态，减少重复传输敏感资料。

确认接口锁定提案行和目标记录，再检查事项及提醒的双版本，或偏好版本。修改、提醒 Outbox 和 APPROVED/result_id 同事务提交。重复浏览器请求、并发确认或更换请求键只执行一次；取消后的提案不能执行。记录改变后返回409，需重新读取和准备。相同运行、同样参数的提案保持幂等，包括取消状态；下一轮可重新准备。

截止和开启提醒的未来日期在准备、确认时分别校验。提醒的实际时间考虑22:00–08:00免打扰，不能超过事项截止；重复提醒必须确认结束日期。提醒当前仅在妮米站内可见，不等于手机或群通知。

## 归档与移除的边界

COMPLETED / ARCHIVED 会同时停用启用中的提醒并写取消 Outbox。ARCHIVED 从日常列表移除，但资料、清单、历史保留；Agent 可搜索归档状态并提议恢复为 ACTIVE，恢复不自动重启旧提醒。归档不等于永久删除。

移除偏好仅删除 memories 中的记录，聊天原文、旧提案和既有运行快照保留，不能声称彻底清除全部个人历史。模型应以 list_memories 当前结果为已保存偏好依据；通用隐私历史删除仍待实现。每空间最多50条偏好的现有配额继续有效。

## 验证范围

专用 nemi_test 集成测试验证确认前不变更、12个并发确认只更新一次、未选清单条目保留、双版本冲突、过期日期不执行、停用保留设置、归档与恢复、偏好保存/编辑/移除/取消、跨空间读取拒绝，以及停止后的 Worker 不能新增提案。

浏览器验收使用真实隔离 API、PostgreSQL、Temporal 和测试专用模型协议替身，覆盖事项/提醒/归档、偏好管理、刷新和手机页面。协议替身不编译进产品；实际供应商模型选择新工具的表现仍需真实账号验收。审批后任意任务自动续接和长期完成验证尚未交付。
